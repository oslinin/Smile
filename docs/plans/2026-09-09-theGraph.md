# The Graph Subgraph + Copilot Integration: Implementation Plan

**Goal:** Replace the brute-force, capped, per-address chain scans that back
the LP Dashboard and the AI Copilot's position tools with a subgraph indexing
`AquaCollateralVault`'s events, then wire the Copilot to query it. Targets
[EthOnline2026's "Best AI Tooling or AI Use Case with The Graph (Continuity)"
bounty](https://ethglobal.com/events/ethonline2026/prizes/the-graph) — Continuity
pool, since this extends the existing `EthOnline2026_continuation_track`
branch rather than starting fresh.

**Branch:** `EthOnline2026_continuation_track` (current).

**Why this is in scope, not bounty-chasing:** the gap is real and already
found twice independently:
- `frontend/components/LPDashboard.tsx` used to show whichever authorization
  was globally most-recently-created (any LP), not the connected wallet's
  own — fixed today with a client-side `eth_getLogs` scan (see commit for
  2026-09-10's Discord thread), documented as a stopgap in
  `docs/limitations.md` L12a.
- `frontend/lib/copilot/chain.ts:112-156` (`readAuths`) is worse: it loops
  every authId from `0` to `nextAuthId`, **hard-capped at `MAX_AUTHS = 50`**
  (`chain.ts:17`). Past 50 authorizations ever created (not 50 *active* —
  50 *total*, ever), the copilot silently stops seeing new ones — including
  its own connected wallet's LP position. `readWalletPositions`
  (`chain.ts:174-248`) compounds this: for every active auth it re-scans
  `MAX_STRIKES_PER_AUTH = 40` strikes on the \$50 grid with N+1 RPC calls to
  find deployed `OptionToken`s, then N+1 more to check balances — no cap on
  correctness there, just on speed and RPC cost.

A subgraph fixes both classes of bug at once (no cap, no N+1) and gives the
Copilot a natural "live blockchain data source" story for the bounty's
AI-agent half.

**Stack:** `graph-cli` + AssemblyScript mappings (`matchstick-as` for unit
tests), local `graph-node` via Docker Compose for dev against Anvil, Graph
Studio for the Sepolia deployment judges will actually query.

## Ground rules

- Never touch `src/vaults/AquaCollateralVault.sol`'s event signatures — the
  subgraph is a pure consumer. If a field is missing from an event (see G2),
  read it via a bound contract call in the mapping, don't change the ABI.
- The `getLogs`-based fixes already shipped in `LPDashboard.tsx` and (after
  G4) `chain.ts` are correctness fallbacks for local Anvil dev, where no
  indexer runs. Never delete them — the subgraph is additive for Sepolia/
  mainnet-class deployments, not a hard dependency for `./local.sh`.
- `cd frontend && npx tsc --noEmit` clean after every task that touches
  `frontend/`. `graph codegen && graph build` clean after every task that
  touches `subgraph/`.
- New package `subgraph/` joins `pnpm-workspace.yaml`'s `packages:` list.

## Words used

- **Subgraph**: a schema + AssemblyScript mappings that a `graph-node`
  compiles, indexes from chain events, and serves as GraphQL.
- **Studio**: The Graph's hosted deploy target (`thegraph.com/studio`) —
  where the Sepolia deployment judges query lives.
- **Data source template**: a subgraph pattern for indexing contracts whose
  *addresses aren't known at deploy time* (here: each `OptionToken`, lazily
  deployed per strike by `AquaCollateralVault.buy()`) — the mapping calls
  `OptionToken.create(address)` the first time it sees that address, and a
  second template picks up that instance's own events from then on.
- **Subgraph MCP**: The Graph's hosted MCP server exposing natural-language
  queries over any of its 15,000+ indexed subgraphs — a separate, optional
  integration point from "the Copilot's own subgraph" (see G6).

## G1: Local subgraph scaffold — Authorization entity

**Files:** create `subgraph/subgraph.yaml`, `subgraph/schema.graphql`,
`subgraph/src/vault.ts`, `subgraph/tests/vault.test.ts`; modify
`pnpm-workspace.yaml`.

**Test first:** `matchstick-as` test `handleRangeAuthorized creates an
Authorization entity with active=true`; `handleAuthorizationRevoked sets
active=false without touching other fields`.

**Implement:**
- `graph init` scaffolding manually (no interactive wizard in CI): data
  source `AquaCollateralVault`, network `localhost` initially (graph-node
  can index any JSON-RPC endpoint, including Anvil — see G3 for the network
  switch to `sepolia`).
- `schema.graphql`: `type Authorization @entity { id: ID! # authId as string
  lp: Bytes! strikeMin: BigInt! strikeMax: BigInt! expiry: BigInt! isCall:
  Boolean! collateralToken: Bytes! maxCollateral: BigInt! usedCollateral:
  BigInt! active: Boolean! createdAtBlock: BigInt! createdAtTimestamp:
  BigInt! }`.
- `vault.ts`: `handleRangeAuthorized` (from `RangeAuthorized`,
  `AquaCollateralVault.sol:168`) creates the entity; `handleAuthorizationRevoked`
  (from `AuthorizationRevoked`, `:169`) loads by `event.params.authId` and
  flips `active = false`.
- ABI: copy `out/AquaCollateralVault.sol/AquaCollateralVault.json`'s ABI
  array into `subgraph/abis/AquaCollateralVault.json` (`graph codegen` needs
  it standalone, not the full Foundry artifact).
**Verify:** `graph codegen && graph build` clean; `graph test` passes.
**Commit:** `feat(subgraph): scaffold with Authorization entity from RangeAuthorized/AuthorizationRevoked`

## G2: Keep `usedCollateral` in sync via bound contract calls

**Files:** modify `subgraph/src/vault.ts`, `subgraph/subgraph.yaml`
(add `OptionBought`, `CollateralReleased`, `PullFailed` as handled events on
the same data source).

**Test first:** `matchstick-as` test using `createMockedFunction` to stub
`AquaCollateralVault.authorizations(authId)` — `handleOptionBought refreshes
usedCollateral from a contract call, doesn't reimplement the pull math`.

**Implement:**
- `RangeAuthorized` doesn't carry `usedCollateral` (starts at 0 anyway) or a
  live `active`/`maxCollateral` after partial fills — rather than
  reimplementing `AquaCollateralVault.sol`'s JIT-pull accounting in
  AssemblyScript (drift risk), `handleOptionBought`, `handleCollateralReleased`,
  and `handlePullFailed` each do one bound `AquaCollateralVault.bind(event.address)
  .authorizations(authId)` call and overwrite `usedCollateral`/`active`
  directly from the return value. One extra `eth_call` per relevant event;
  negligible at this event volume.
**Verify:** `graph test` passes; manually confirm against `cast call` output
for a live authId on Anvil (matches the value from the earlier Discord
debugging session's `cast call ... authorizations(uint256)...` command).
**Commit:** `feat(subgraph): refresh usedCollateral/active from a bound contract call, not reimplemented math`

## G4: Wire the frontend to the subgraph (Sepolia + local dual-mode)

**Files:** create `frontend/lib/subgraph.ts`; modify
`frontend/components/LPDashboard.tsx`, `frontend/lib/copilot/chain.ts`,
`frontend/.env.example`.

**Test first:** none new (existing `npx tsc --noEmit` gate); manual check —
LPDashboard shows both of a test LP's active ranges once G7's stretch entity
exists, or just the correct one immediately after G4 if scoped to
Authorization only.
**Implement:**
- `NEXT_PUBLIC_SUBGRAPH_URL` env var (Studio query URL once G5 deploys;
  `http://localhost:8000/subgraphs/name/smile/local` for dev). `lib/subgraph.ts`
  exports `querySubgraph<T>(query, variables)` — a thin `fetch` POST wrapper,
  no GraphQL client dependency needed for this query volume.
- `LPDashboard.tsx`'s `refreshMyAuth` (added in the 2026-09-10 fix): when
  `NEXT_PUBLIC_SUBGRAPH_URL` is set, query
  `{ authorizations(where: {lp: $lp, active: true}, orderBy: createdAtBlock,
  orderDirection: desc) { id strikeMin strikeMax expiry isCall collateralToken } }`
  instead of the `eth_getLogs` scan. Keep the `getLogs` path as the fallback
  when the env var is unset (local Anvil dev without the G3 container
  running) — this is the "never delete the fallback" ground rule.
- `chain.ts`'s `readAuths`: same swap, dropping `MAX_AUTHS` entirely when the
  subgraph is available (the cap only exists because the current version
  can't paginate cheaply — the subgraph can).
**Verify:** `npx tsc --noEmit` clean; with `NEXT_PUBLIC_SUBGRAPH_URL` pointed
at G3's local endpoint, LPDashboard and the copilot's `get_positions` tool
both return the same authorizations the direct `cast call` shows.
**Commit:** `feat(frontend): query the subgraph for LP authorizations, getLogs as fallback`

## G6 (stretch): Long-option positions via dynamic data sources

**Files:** modify `subgraph/subgraph.yaml` (add `OptionToken` as a
`templates:` entry), `subgraph/schema.graphql`, `subgraph/src/vault.ts`,
create `subgraph/src/optionToken.ts`.

**Test first:** `matchstick-as` test `handleOptionBought instantiates an
OptionToken template exactly once per token address`; `optionToken.test.ts`:
`Transfer events update a Position entity's balance, zero-balance positions
are removed, not zeroed`.
**Implement:**
- `handleOptionBought` calls `OptionToken.create(event.params.optionToken)`
  the first time that address is seen (track via a `Bytes[]` set on the
  parent `Authorization`, or rely on the subgraph runtime's own dedup —
  confirm which before writing the guard).
- `optionToken.ts`'s `handleTransfer`: standard ERC-20 balance-per-holder
  bookkeeping into a `Position` entity keyed `${token}-${holder}`, replacing
  `chain.ts`'s `MAX_STRIKES_PER_AUTH`-bounded strike-grid + balance-fan-out
  scan entirely.
**Verify:** `graph test` passes; a Sepolia test buy shows up in
`{ positions(where: {holder: $addr}) { ... } }` without the strike grid scan.
**Commit:** `feat(subgraph): index long OptionToken positions via dynamic data sources`
